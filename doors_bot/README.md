# doors_bot — QQ 群活跃统计与 Robux 结算 (v2.5.5)

QQ 群发言统计 + 每月按分数发 Robux 的 AstrBot 插件，跑在 NapCat（OneBot v11 反向 WS）上。

机器人在群里不聊天、也不主动发言。群消息进来只做记录和计分，看榜、自检、改数据都在
AstrBot 后台的聊天窗里敲指令。唯一能在群里用的指令是 `/新人绑定`（邀请人认领自己拉进来的
新人），它也只改库、在群里不回话，绑没绑上后台看。

## 计分

- 一条有效发言 +0.05 分，单日发言分封顶 3 分
- 当天有效发言 ≥10 句再 +1 分，所以单日最多 4 分。拿满之后日榜的得分格写成
  `4 已达今日上限`
- 有效发言 = 纯文本消息。图片、表情包、视频、@ 机器人、指令消息都不算
- 一条消息前后 120 秒内（含本人）要有 ≥2 个不同的人在说话才计分。可以追溯：
  第二个人开口后，第一个人还在这 120 秒里的消息也一起算上
- 防刷屏的几道过滤，按顺序判：
  - 同一人 5 秒内的多条只记 1 条
  - 同一人连发、中间没别人插话：60 秒内的全部并成 1 条（`turn_gap_seconds`）；
    有人插话后恢复逐条计数
  - 内容和本人上一条完全相同 → 不计（`content_dedup`）
  - 单字符或纯数字 → 不计（`meaningless_filter`，挡 1/2/3 接龙）
- `no_score_qqs` 名单里的号（群内机器人、公告号）完全不参与：发言不入库、不加分、
  不吃扣分、不上榜。他们的话也不算上面那条的"有人在说话"，所以真人单独对着机器人
  刷屏拿不到分。名单之前已经入库的历史发言一并排除，不用清库

## 扣分

当天没有有效发言的在群成员 -0.2 分，从当月已有分数里扣，扣到 0 为止，不会出现负分。
名单来自每小时的群成员同步，退群的人（`in_group=0`）不再扣。

## 月度结算

月度总分 = max(0, 当月日分和) × 新人系数 × 连续获奖衰减系数 + 上月结转 + 邀请奖励分

- 新人系数 ×1.1：入群当月和次月有效。退了又进的人永久不算新人
  （`join_history` 是入群流水，同一 QQ 攒到 2 条就算回流）
- 衰减系数：连续 n 个月获奖，下月日常分 ×(1-0.5n)，默认衰减率 0.5，连续 2 个月获奖
  后本月日常分归 0。结转分和邀请分不受系数影响
- 前 `top_n`（默认 10）名获奖，每份 `award_per_top`（默认 50R）。奖金池封顶 =
  名额数 × 单份，默认 500R，一分都不会超发
- 名次并列共享（1、2、2、4 式），同一组并列的人拿一样多：
  - 装得下剩余名额 → 每人各拿一份（前面 7 人无并列，第 8 名 3 人并列正好占满 8~10 名）
  - 装不下 → 整组平分这组占掉的剩余名额（第 7 名起 7 人并列 → 平分第 7~10 名的
    (10-7+1)×50 = 200R，每人 28.57R）。零头向下取到 2 位小数，留在池子里不发出
- 获奖的人总分清零，没获奖的按 5% 结转到下月
- 结算写进 `month_score`（含 `robux` 应发数），同时在与库同目录下生成
  `pay_list_YYYY-MM.txt` 发放名单。幂等，重跑会先提示

## 拉新与邀请关系

新人入群后 10 天内（`window_days`），每天有效发言都 >10 条，或日均 ≥20 条，
邀请人 +10 分，一个人只奖一次（`newbie_bonus` 表记着）。被拉的新人自己不加这 10 分。

谁拉的这个人，插件有两种拿法，各管一半、互不翻案：

1. 自动检测。入群通知 `group_increase` 里带 `operator_id`。这里有个坑：
   "管理员点同意批准入群"时，`operator_id` 是那个审批人，不是拉人的人。
   所以审批放行那一次不算邀请（`join_kind` 记 `approve`，`invited_src` 记 1，
   库里留着是谁放行的只作核对），**审批人拿不到拉新分**
2. 邀请人自己确认。每次入群开一个默认 5 分钟的窗口（写进 `pending_bind`），
   邀请人在群里发 `/新人绑定 <新人QQ>` 就把这条关系确认下来，`invited_src` 记 2。
   只有在没检测出邀请人的时候（审批放行、二维码入群、入群那会儿插件不在线）
   才由绑定说了算。**已经自动检测到邀请人的，别人再来绑会被挡掉**——不然谁都能
   把别人的新人绑到自己头上刷那 10 分；确实是自己拉的就请检测到的那个人本人
   再发一次，那只算人工确认
3. 管理员代填。后台聊天窗里的发送者不是 QQ 号，所以那条指令在那里要写成
   `/新人绑定 <新人QQ> <邀请人QQ>`，由管理员指名邀请人。这一种可以覆盖自动检测的
   结果（用于修正检测错了的场景），群里那种自证的写法不能

窗口超时或者没人理会照旧用自动检测的结果记账，不会作废也不会扣分。
二维码、群号搜索这类主动入群没有邀请人（`operator_id` 为 0 或等于本人），
`join_kind` 记 `link`，榜上备注写"自己搜群号入群，无邀请人"。
这种入群方式也照样开确认窗口：把群号或链接发给朋友也算拉人，谁发 `/新人绑定`
认领就记在谁头上，备注变成"本人已确认"，这一条是本人自证的，管理员对着榜单核即可。

备注里只写"邀请人是谁"，不解释这人是怎么进群的，一共六种写法：
"邀请人 xx(本人已确认)"（邀请人自己在群里发的）、"邀请人 xx(管理员代填)"
（后台带两个参数由管理员填的）、"邀请人 xx(未确认)"（只有自动检测、还没人绑定）、
"邀请人待定(管理员放行，绑上才算拉新)"（审批入群，名字先不写出来，等谁绑定写谁）、
"自己搜群号入群，无邀请人"、"邀请人未记到(入群那会儿插件不在线)"。

插件不在线时进的人开不出窗口（窗口要有精确到秒的入群时刻才算时限），
只能等成员同步回填补一条入群记录，入群时间也从那时补。

## 后台指令

在 AstrBot WebUI 聊天窗里发（QQ 群/私聊发这些不会有反应）。每条都支持 `日榜`、`.日榜`、
`//日榜`、`/日榜` 四种写法。

只读，随时发：

| 指令 | 说明 |
|-|-|
| `/日榜 [日期]` | 不带参数 = 今天 00:00 到当前的实时榜；带日期 = 指定那天，`/日榜 2026-09-24`、`/日榜 昨天`、`/日榜 24` |
| `/昨日榜` | 昨天全天（含未发言扣分） |
| `/月榜 [月份]` | 不带参数 = 本月 1 号到今天的总分实时预估（按结算系数预演，含结转/邀请/手工扣分）；带月份 = `/月榜 2026-08`、`/月榜 上月`、`/月榜 9` |
| `/上月榜` | 上月；已结算读库并带 Robux 应发列，未结算给预估 |
| `/查询 <QQ>` | 单人档：今天/本月句数与得分、自检测起累计、昵称、入群时间、邀请关系、游号绑定、QQ 会员。入群时间优先现调接口（到秒、显示到分钟），NapCat 不在线用每小时同步存进库的 `join_ts`（同样到分钟），两边都没有才退回只到日的日期；会员一栏拿不到就写"未知" |
| `/自检` | 库路径与最后写入时间、各表行数、待补算日期、本月手工调整、邀请确认窗口、成员同步结果、各定时任务下次触发时间 |

会改数据，要二次确认：

| 指令 | 说明 |
|-|-|
| `/补跑` | 立刻补算所有"有发言却没有日分"的已过日期（和每 30 分钟的自愈同一条规则） |
| `/同步` | 立刻向 NapCat 拉一次全群名单。只覆盖 `members`、回填 `join_log`，不动任何分数，发一次就跑 |
| `/重置日 [日期]` | 按 `msg` 原始记录重算某天（默认今天；没过完的当天不做未发言扣分） |
| `/重置月 [月份]` | 重算整月（默认本月；不动结转分、邀请分和手工扣分） |
| `/删除 <QQ> [月份]` | 删掉某人本月全部记录（日分 + 月榜行），本月从零重新计，回显被删的行 |
| `/扣除 <QQ> <分数> [月份] [原因]` | 手工扣分，记进 `score_adjust`。独立于日分，`/重置日`、`/重置月`、`/补跑` 都抹不掉它，结算时计入总分（总分最低到 0） |
| `/结算 [月份]` | 立即结算某月，会先补跑该月漏算日。月份还没过完时预览会额外警告还剩几天 |

第一次发只回一份"将要改什么"的预览（碰多少行、现在的分数、会不会撞到已结算的月份），
原样再发一次、末尾加 `确认`才真跑：

```
/重置日 昨天
/重置日 昨天 确认
```

改数据的指令执行后在 AstrBot 日志留一行 `[doors_bot] 后台操作 ...`。

日期参数认：`今天/今日`、`昨天/昨日`、`前天`、裸日 `24`、`2026-09-24`、`2026/09/24`、
`09-24`、`20260924`。月份参数认：`本月/当月`、`上月/上个月`、裸月 `9`、`2026-09`。

## 群内指令

| 指令 | 说明 |
|-|-|
| `/新人绑定 <新人QQ>` | 邀请人本人在群里确认"这个人是我拉进群的"。入群后 5 分钟内有效（`invite_bind.window_minutes`） |
| `/新人绑定 <新人QQ> <邀请人QQ>` | 同一条指令在 AstrBot 后台聊天窗里的写法：发送者不是 QQ 号，所以邀请人要写出来，由管理员代填 |

这条在群里发**机器人不回话**：它只改库、在 AstrBot 日志留一行，群里唯一会说话的是
配置页打开 `invite_bind.prompt` 之后入群时的那句提示（默认关）。绑没绑上以后台为准：
绑成之后榜单备注显示"邀请人 xx(本人已确认)"，拉新奖励按绑的那个人发。
后台代填的那一条会回全文，并且在结果里标出"管理员代填"。

两种写法都不能把已经自动检测到的人换掉：入群事件认到是 A 拉的，B 来发
`/新人绑定` 会被挡下（不挡的话谁都能抢别人的新人去刷那 10 分），要改判只能
管理员在后台带上第二个参数代填。入群那一刻插件不在线的人没有确认窗口，
群里这种自证写法不受理，也只能走后台代填。

以下情况会被挡下：机器人自己（在不计分名单里）、把自己绑成自己的邀请人、
这人退了又进（不是新人，没有邀请奖励）、入群那会儿插件不在线（没有窗口，
只能用自动检测的结果）。

## 榜单长什么样

```
发言日榜 2026-09-24 00:00 ~ 23:59
  名次  用户                              QQ                      得分      句数  备注
     1  示例昵称甲                        1000000001    4 已达今日上限        82  拉新 +10（示例昵称乙 达标）
     1  示例昵称丙                        1000000003    4 已达今日上限        64
     3  示例昵称乙                        1000000002              2.25        25  新人09-12入群，邀请人 示例昵称甲(本人已确认)
     4  这是一个超级无敌长长长到不完的.   1000000004               1.1           12
注: 得分里的"已达今日上限"= 当天把单日上限 4 分拿满了（发言分上限 3 + 达量奖励 1）

发言月榜 2026-09-01 ~ 2026-09-30 (已结算)
  名次  用户                              QQ                  总分     应发Robux  备注
     1  示例昵称甲                        1000000001          12.5           50R  拉新 +10（示例昵称乙 达标）
     2  示例昵称丙                        1000000003           9.9           50R
     3  这是一个超级无敌长长长到不完的.   1000000004           8.2           50R
     4  示例昵称乙                        1000000002          3.15             -  新人09-12入群，邀请人 示例昵称甲(本人已确认)
```

显示口径：

- 前几列一律定宽：名次 6、用户 32（= QQ 昵称的最大显示宽度，短名字也补满）、QQ 12、
  分数 10（日榜 14，得分后面要跟一句"已达今日上限"；上限配成两位数时这列自己加宽）、
  句数 8。每行第 N 列都从同一个位置开始，和这行内容长短无关，超宽就截断补 `.`
- 备注在最后面，不占列宽也不补齐，写多长都挤不歪前面的列。里面只有两种话：
  新人那行出入群日期与邀请人，邀请人那行出本月因拉新加的分
- 同分并列名次（1、2、2、4 式）。并列的几行内部：日榜按句数多者在前，句数相同按 QQ 升序；
  月榜没有句数列，按 QQ 升序，保证每次打开顺序一样
- 0 分的行不显示。`report.display_limit` 设 0（默认）不限量，设正数截断并提示"另有 N 行未显示"
- 昵称里会让列位漂移的字符在显示前清掉，库里原文不动：双向控制符（U+202D/U+2067 等）、
  零宽连接符、变体选择符；看着是空格但宽度随字体浮动的韩文填充符、不间断空格（换成普通空格）；
  emoji 与装饰符号（🤔 ✨ ❤ ■ ⭐ 箭头等，浏览器用彩色字体画，宽度既不是 1 也不是 2）；
  翻文字工具造出的反转字母（ʞ ɐ ʍ ǝ 这类 IPA/修饰字母，`suʞɐʍ` → `su`）
- 昵称被清成空串（纯 emoji 名字）时该行退回显示 QQ 号
- 清完之后列内只剩"汉字 2 列 / 其他 1 列"。要是还歪，多半是浏览器把某个
  East-Asian-Ambiguous 符号按 2 列渲染了，把那行原文发出来再补规则
- 输出不带 emoji，后台侧自动包一层 ``` 代码块防止前端折叠空格导致错位
- 不需要 `chcp 65001`；只有昵称里本来就带 emoji 时在 GBK 窗口会显示成 `?`，不影响数值

## 数据放在哪

| 内容 | 位置 |
|-|-|
| SQLite 库 | `<AstrBot根>/data/plugins/doors_bot_data/doors.db` |
| 每月发放名单 | 与库同目录的 `pay_list_YYYY-MM.txt` |
| 插件代码 | `<AstrBot根>/data/plugins/doors_bot/`（可随时删除/覆盖） |

库和发放名单都在 `doors_bot_data`，与插件目录 `doors_bot` 同级、在它外面。
AstrBot 卸载或更新插件只操作 `data\plugins\doors_bot`，勾"同时删除数据"删的是
`data\plugin_data\doors_bot`，两条都碰不到这个库。

要注意的几点：

- 手工清空整个 `plugins` 目录（或"清空 plugins 重装全部插件"）会连它一起删。
  这样操作前先复制一份 `doors.db`。想让库彻底离开 `plugins`，`db_path` 填一个
  `plugins` 之外的绝对路径即可，行为一样
- 库路径不再受 `.env` 影响。旧版 `.env` 的 `DB_PATH=./doors.db` 是相对路径，
  配合启动目录的不确定性，会在插件目录里凭空多出第二个库，删插件时一起没了
- `db_path` 留空走默认位置；填绝对路径按填的位置用；只填文件名则放进默认数据目录。
  想整个换目录可以设环境变量 `DOORS_BOT_DATA_DIR`
- `db_path` 里不要写 `../`：相对值不会被当成"相对插件目录"，而是拼到默认数据目录后面，
  结果往往和留空一样，看起来改了没生效。要精确控制位置就写绝对路径
- 旧库不会被自动移动或删除。升级后如果默认位置变了，`/自检` 的"遗留库探测"会列出
  插件目录内、AstrBot 根目录、以及 v2.4.0 的 `<AstrBot根同级>\doors_bot_data\doors.db`，
  需要人工确认后自己搬（停服后复制文件，或用 SQLite 工具导出导入）。
  升 v2.4.1 前先停服确认 `db_path`：留空的话新位置是空库，要么把旧库文件搬进
  `data\plugins\doors_bot_data\`，要么把 `db_path` 显式指向旧库位置，二选一，
  别两边各留一份在跑

存档形式：

- 每天 → `daily_score` 一人一行（`date`/`score`/`sentences`，含未发言的负分）
- 每月 → `month_score`（`total`/`rank`/`robux`/`carry`/`bonus`/`settled`）+ 同目录发放名单文本
- 原始发言 → `msg` 一直留着，所以 `/重置日`、`/重置月`、`/补跑` 都能按原始记录重算

要自己的报表就直接查 `doors.db`：

```sql
-- 某日发言榜（日分 + 句数）
SELECT qq, score, sentences FROM daily_score
WHERE date='2026-09-01' ORDER BY score DESC;

-- 当月累计（日分合计 + 结转 + 邀请分）
SELECT s.qq, u.name, SUM(s.score) + COALESCE(m.carry,0) + COALESCE(m.bonus,0) AS total
FROM daily_score s
LEFT JOIN month_score m ON m.qq=s.qq AND m.month='2026-09'
LEFT JOIN user_info u ON u.qq=s.qq
WHERE s.date LIKE '2026-09%'
GROUP BY s.qq ORDER BY total DESC;

-- 上月最终结算榜（robux 列就是应发）
SELECT rank, qq, total, robux FROM month_score
WHERE month='2026-08' AND settled=1 ORDER BY rank;

-- 谁是谁拉进来的（join_ts 是 NapCat 的 join_time，epoch 秒；老成员由成员同步回填）
SELECT l.qq, u.name, l.join_date, datetime(l.join_ts,'unixepoch','localtime') AS 入群时刻,
       l.invited_by, l.invited_src, l.join_kind
FROM join_log l LEFT JOIN user_info u ON u.qq=l.qq;
```

## 表

`msg` 原始有效候选消息 · `daily_score` 日分 · `month_score` 月总分
（total/rank/robux/carry/bonus/settled）· `join_log` 最新一次入群记录
（invited_by/invited_src/join_kind/join_ts）· `pending_bind` 待确认的邀请关系窗口 ·
`join_history` 入群流水（≥2 条 = 回流）· `members` 全群成员快照（in_group、入群日期、
入群时刻 join_ts）· `user_info` 昵称 · `award_history` 获奖史 · `newbie_bonus` 已发的邀请奖 ·
`score_adjust` 手工调整（`/扣除` 写的负分，按月记，重算日分抹不掉）· `bind` QQ↔Roblox

`bind` 表目前还是人工维护，插件不自动写。旧库无损迁移：启动时自动 `ALTER TABLE` 加列，
已有数据保留（`join_log.invited_by` 非零的老记录会被回填成 `invited_src=1`）。

## 数据没涨 / 榜没刷新

先在后头发 `/自检`，对着一行一行看：

- `数据库:` 路径和"改动时间"。改动时间停在昨晚 = 插件根本没跑，或者写到了别的库。
  "遗留库探测"列出了别的 `doors.db` = 历史上产生过第二个库，以哪个为准要人工确认
- `最近发言:` 是"无" = `msg` 没进来消息。群号配错、平台不是 NapCat、或者消息被过滤器挡了
- `本月待补算日:` 有日期 = 那天 23:59 的任务没跑（机器关机 / AstrBot 没开）。
  补跑任务或 `/补跑` 会自己追回来，分数直接出现在 `/月榜`，不用等明天
- `成员同步:` "从未"或带错误 = 未发言扣分名单和新人加成会不准。两个常见原因：
  AstrBot 刚启动时 NapCat 的反向 WS 还没连上（v2.5.1 起按 2/5/10/20/40/80/160 秒退避重试）；
  定时任务不在消息事件上下文里、接口认不出该走哪条连接（v2.5.2 起自动带 `self_id`）。
  等不及就发 `/同步`。"本轮 N 次"是这次试了几轮，"走 self_id"/"走 默认"是走的哪条路。
  同步成功但仍报 `ApiNotAvailable` = NapCat 侧 QQ 掉线或反向 WS 没连上：
  看 `logs/napcat.log` 末尾有没有登录二维码，`astrbot.log` 里有没有
  `aiocqhttp(OneBot v11) 适配器已连接。`——没连上时消息同样不会入库
- `邀请确认窗口:` 有几个待确认、窗口多长、指令开没开、已经人工确认几个人。
  一个都没有 = 入群通知根本没进来（下面这条）
- 邀请奖励/新人加成一个不发：先看 `join_log` 有没有行。入群通知（`group_increase`）在
  AstrBot 里会被转成群消息类型，v2.5.3 起处理器放开到全部事件类型才收得到。
  只有"有人拉"和"管理员审批"才有 `operator_id`，群号搜索、二维码主动入群是 0 或等于本人。
  日志里对应 `新成员加入 <QQ> 邀请人 <QQ> 方式 <sub_type>`

还不清楚就把主配置 `log_level` 临时调到 `DEBUG`，插件失败细节会直接打在控制台。
只想立刻看结果：`/补跑` → `/月榜 本月`。怀疑某天算错：`/日榜 该日` 和 `/重置日 该日` 对比。

## 已知局限

- 插件装之前就进群的人，入群时间拿得到、邀请人拿不到。OneBot 11 的群成员接口
  （`get_group_member_list` / `get_group_member_info`）只回 `join_time` 这类资料，
  没有"谁拉进来的""怎么进群的"这种字段——邀请人只在实时的入群通知 `group_increase`
  里以 `operator_id` 出现一次，插件当时不在线就补不回来。所以老成员的入群时间由
  每小时同步从 `join_time` 回填（`members.join_ts`、`join_log.join_ts`，精确到秒），
  备注只能写"邀请人未记到(入群那会儿插件不在线)"
- 机器人上线前进群、而且上线前从没被同步进 `members` 快照的人，如果他"退了又进"
  发生在插件首次同步之前，判不出回流
- 整天一条消息都没有时，分不清是机器离线还是群里没人说话。所以补跑只重算
  "有发言记录却没有日分"的日期，不会替整天离线补未发言扣分
- QQ 空间黄钻在这个客户端的接口里没有对应字段，`/查询` 查不到，只能人工看空间
- 群内除了 `/新人绑定` 不提供任何查询指令，榜单都要在后台看
