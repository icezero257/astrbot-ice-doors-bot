# Doors Bot - QQ群活跃统计 & Robux发放 (v2.5.3)

基于 AstrBot v4 + NapCat 的 QQ 群活跃统计与 Robux 奖励插件。

**QQ 群内纯静默：不回复、不主动发送任何消息；查榜与运维指令只在 AstrBot 后台聊天窗可用。**

## 功能总览

- 静默统计目标群有效发言（纯文本、5秒去重、120秒多人窗口计分）
- 每日自动计分 / 未发言自动扣分（扣完为止，不为负）
- **漏算自愈**：每 30 分钟（可配）扫描"有发言记录却没有日分"的已过日期并自动补算，
  机器关机、AstrBot 没在 23:59 运行、月首结算前都会自动追回分数
- 新人邀请奖励（可选）：新人入群 10 天内每日有效发言 >10 条，或日均 ≥20 条 → 邀请人 +10 分
- **防回流卡加成**：所有入群事件登记流水（`join_history`），
  退了又进的人永久失去新人加成与邀请奖励资格
- 月度自动结算：新人系数 × 连续获奖衰减系数 + 上月结转 + 邀请分
- Top N 奖励判定（前 N 名含并列，每人一份，并列不缩水），Robux 应发数落库
- 定时同步全群成员名单（扣分名单、退群标记 `in_group`、入群时间回填 → 新人加成）
- 数据全部落在**插件目录之外**的 `data/plugins/doors_bot_data/`（与插件同级），删插件、换版本都不会丢库

## 计分规则（可全部在配置页调整）

1. 每 1 条有效发言 +0.05 分，单日发言分上限 3 分
2. 当日有效发言 ≥10 句额外 +1 分（单日上限 4 分）
3. 有效发言 = 纯文本消息（图片/表情包/视频/@/指令消息均不计）
4. 防刷屏去重（入库时依次判定）：
   - 同一人 5 秒内多条只计 1 次
   - 同一人连续一串消息、中间无他人插话：60 秒内的全部合并算 1 条
     （`turn_gap_seconds` 可调；有他人插话后恢复正常逐条计数）
   - 内容与本人上一条完全相同 → 不计（`content_dedup` 开关）
   - 单字符或纯数字消息 → 不计（`meaningless_filter` 开关，防 1/2/3 接龙刷屏）
5. 一条消息前后 120 秒窗口内（含本人）≥2 个不同发言者才计分
   （可追溯：第二人开口后，第一人在窗口的消息也计分）
6. `no_score_qqs` 名单里的QQ（群内机器人、公告号）**完全不参与**：发言不入库、不加分，
   也不吃未发言扣分，不会出现在任何榜单上；他们的话同样**不算**第 5 条里的"有人接话"，
   所以真人单独对着机器人刷屏不会得分。历史上已入库的发言也会被一并排除，无需清库
7. 当天没有有效发言的在群成员 -0.2 分，从当月已有分数中扣，不出现负分
8. 月度总分 = max(0, 当月日分和) × 新人系数(×1.1，入群当月及次月)
   × 衰减系数(连续 n 月获奖 ×(1-0.5n)，即连续 2 月获奖后本月日常分归 0) + 上月结转 + 邀请奖励分
9. 前 10 名(含并列)每人 50 Robux：并列第 8 名有 4 个人就 4 人各拿 50，不平分；
   名次按"并列共享名次"算，所以获奖人数可能超过 10
10. 获奖者总分清零，未获奖者总分 ×0.05 结转到下月

## 后台查看与运维（QQ 内机器人永远沉默）

在 **AstrBot WebUI 聊天窗**（仅该平台生效，QQ 群/私聊发这些指令无任何响应）：

| 指令 | 说明 |
|-|-|
| `/日榜 [日期]` | 不带参数＝今日 00:00 至当前的实时榜；带日期＝指定日榜，如 `/日榜 2026-09-24`、`/日榜 昨天`、`/日榜 24` |
| `/昨日榜` | 昨日全天榜（含未发言扣分） |
| `/月榜 [月份]` | 不带参数＝本月 1 号至今的总分实时预估（含结转/邀请/手工扣分，按结算系数预演）；带月份＝指定月份，如 `/月榜 2026-08`、`/月榜 上月`、`/月榜 9` |
| `/上月榜` | 上月榜；已结算则读库并带 **Robux 应发列**，未结算则实时预估 |
| `/自检` | 库路径与最近写入时间、各表行数、待补算日期、本月手工调整、成员同步结果、任务下次触发时间 |

会改数据的运维指令（每条都必须二次确认，见下）：

| 指令 | 说明 |
|-|-|
| `/补跑` | 立刻补算所有"有发言却无日分"的已过日期（自愈同规则，定时每 30 分钟一次） |
| `/同步` | 立刻向 NapCat 拉一次全群成员名单（默认每小时一次；只改 members 与回填 join_log，不动任何分数） |
| `/重置日 [日期]` | 立即按发言记录重算某天（默认今天；未过完的当天不做未发言扣分） |
| `/重置月 [月份]` | 立即按发言记录重算整月（默认本月；不动结转分、邀请分与手工扣分） |
| `/删除 <QQ> [月份]` | 删除某人本月全部记录（日分 + 月榜行），该人本月从零重新计分；回显被删行 |
| `/扣除 <QQ> <分数> [月份] [原因]` | 手工扣某人某月若干分（写 `score_adjust`，重算日分抹不掉，结算时计入总分，总分最低到 0） |
| `/结算 [月份]` | 立即结算某月（幂等，会先补跑该月漏算日）。月份尚未过完时预览里会额外警告还剩几天没结算 |

**二次确认**：这类指令第一次发只会回显"将要改什么"的预览（涉及多少行、现状分数、
会不会碰到已结算的月份），并提示原样再发一次、末尾加 `确认`：

```
/重置日 昨天
/重置日 昨天 确认        ← 这一条才真正执行
```

写数据类指令执行后会在 AstrBot 日志留一行 `[doors_bot] 后台操作 ...` 记录。

日期/月份参数支持：`今天/今日`、`昨天/昨日`、`前天`、裸日 `24`、`2026-09-24`、
`2026/09/24`、`09-24`、`20260924`；月份支持 `本月/当月`、`上月/上个月`、裸月 `9`、`2026-09`。
四种触发写法均可命中：`日榜`、`.日榜`、`//日榜`、`/日榜`。

榜单一律不显示 0 分的行；`report.display_limit` 设 0（默认）表示不限量、完整显示。

也可以完全不开 AstrBot，用命令提示符本地查（只读库，不写任何数据）：

```bat
cd /d <实例路径>
python data\plugins\doors_bot\cli.py all        # 今日/昨日/本月/上月 四张榜
python data\plugins\doors_bot\cli.py today      # 今日实时榜
python data\plugins\doors_bot\cli.py yesterday  # 昨日日榜
python data\plugins\doors_bot\cli.py day 2026-09-24
python data\plugins\doors_bot\cli.py day 昨天
python data\plugins\doors_bot\cli.py month 2026-08
python data\plugins\doors_bot\cli.py lastmonth  # 上月结算榜
python data\plugins\doors_bot\cli.py diag       # 自检
python data\plugins\doors_bot\cli.py today --db <实例路径>\doors.db
```

```
发言日榜 2026-09-24 00:00 ~ 23:59
  名次  用户                              QQ                  得分      句数  备注
     1  示例昵称甲                        1000000001             4        82  （已抵达今日上限）
     1  示例昵称丙                        1000000003             4        64  （已抵达今日上限）
     3  示例昵称乙                        1000000002          2.25        25
     4  这是一个超级无敌长长长到不完的.   1000000004           1.1        12
注: 单日上限 4 分（发言分上限 3 + 达量奖励 1）

发言月榜 2026-09-01 ~ 2026-09-30 (已结算)
  名次  用户                              QQ            总分        应发Robux
     1  示例昵称甲                        1000000001          12.5            50R
     2  这是一个超级无敌长长长到不完的.   1000000004           8.2            50R
     3  示例昵称乙                        1000000002          3.15              -
```

表格显示口径：

- **每一列都是固定宽度**：名次 6、用户 32（＝QQ 昵称的最大显示宽度，短名字也会补满）、
  QQ 12、分数 10、句数 8。每行第 N 列都从同一个字符位置开始，与这一行的内容长短无关；
  超过列宽的内容截断并补 `.`
- `（已抵达今日上限）` 这类备注放在**最后一列**，它后面没有别的列，写多长都挤不歪表格
- 昵称里的"错宽字符"会被整族清掉（只影响显示，库里存的还是原名）：
  双向控制符（U+202D/U+2067 等）、零宽连接符、变体选择符，
  以及"看着是空格其实按字体浮动宽度"的韩文填充符/不间断空格（换成普通空格）；
  **emoji 与装饰符号**（🤔 ✨ ❤ ■ ⭐ 箭头等，浏览器用彩色字体绘制，宽度既不是 1 也不是 2）；
  **翻文字工具造出的反转字母**（ʞ ɐ ʍ ǝ 这类 IPA/修饰字母，`suʞɐʍ` → `su`）。
  这些字符参与浏览器排版却不参与宽度计算，是过去几版错位的真正原因
- 昵称被清成空串时（纯 emoji 名字）该行退回显示 QQ 号
- 清完之后列内只剩"汉字 2 列 / 其他 1 列"，残余误差不应再出现；
  若还歪，多半是浏览器把某个 East-Asian-Ambiguous 符号按 2 列渲染，把那一行的原文发出来再补规则
- **同分并列名次**（1、2、2、4 式），不按顺序硬编 1、2、3、4
- 并列的那几行内部再排：**日榜按句数多者在前**（同是 4 分（已达上限）时谁刷得多谁在上面），
  句数也相同则按 QQ 升序；月榜没有句数列，并列按 QQ 升序，保证每次打开顺序一致
- 0 分的行不显示；`report.display_limit` > 0 时截断并提示"另有 N 行未显示"

数据库定位顺序：`--db` > WebUI 插件配置页的 `db_path` > 默认数据目录（见下节）。
榜单本身不再需要 `chcp 65001`；只有昵称里自带 emoji 时在 GBK 窗口会显示成 `?`，不影响数值。

## 数据存在哪里 / 为什么删插件不会丢

| 内容 | 位置 |
|-|-|
| SQLite 库 | `<AstrBot根>/data/plugins/doors_bot_data/doors.db` |
| 每月发放名单 | 与库同目录的 `pay_list_YYYY-MM.txt` |
| 插件代码 | `AstrBot/data/plugins/doors_bot/`（可随时删除/覆盖） |

- 例：AstrBot 装在 `<实例路径>\AstrBot`，库就在
  `<实例路径>\AstrBot\data\plugins\doors_bot_data\doors.db` —— 与 `doors_bot` **同级但不在其内**。
  AstrBot 卸载/更新插件只操作 `data\plugins\doors_bot` 这一个目录，勾"同时删除数据"删的是
  `data\plugin_data\doors_bot`，两条都碰不到同级的 `doors_bot_data`。
- 唯一的软肋：**手工清空整个 `plugins` 目录**（或"清空 plugins 重装全部插件"）会连它一起删。
  每次这样操作前先复制一份 `doors.db`。想让库完全脱离 `plugins`，`db_path` 填一个 `plugins`
  之外的绝对路径即可（如 `<实例路径>\doors_bot_data\doors.db`），行为一致。
- 库路径**不再受 `.env` 影响**。旧版 `.env` 里 `DB_PATH=./doors.db` 是相对路径，
  配合启动目录的不确定性，会在插件目录里凭空建出第二个库，删插件时数据一起消失。
- 配置页 `db_path` 留空即走上面的默认位置；填绝对路径按填写位置使用；
  只填文件名则放到默认数据目录下。想换目录可设环境变量 `DOORS_BOT_DATA_DIR`。
- `db_path` 里**不要写 `../`**：相对值（含 `..`）不会被当成"相对插件目录"，而是拼到默认数据目录后面，
  结果往往和留空一样，看起来"改了没生效"。要精确控制位置就写绝对路径。
- 旧库不会被自动移动或删除：升级后若默认位置变了，`/自检` 的 `遗留库探测` 会列出插件目录内、
  AstrBot 根目录、以及 v2.4.0 的 `<AstrBot根同级>\doors_bot_data\doors.db`，
  需要人工确认后再把数据并过去（停服后手工复制，或用 SQLite 工具导出导入）。
  **升级 v2.4.1 前请先停服并确认 `db_path`**：留空的话新默认位置是空库，需把旧库文件搬到
  `data\plugins\doors_bot_data\`（或把 `db_path` 显式指向旧库位置，二选一）。

每日/每月的存档形式：

- 每一天 → `daily_score` 表一行一人（`date`/`score`/`sentences`，含未发言的负分）
- 每一月 → `month_score` 表（`total`/`rank`/`robux`/`carry`/`bonus`/`settled`）
  + 同目录 `pay_list_YYYY-MM.txt` 文本发放名单
- 原始发言 → `msg` 表一直保留，所以 `/重置日`、`/重置月`、`/补跑` 都能按原始记录重算

需要实时榜单时直接查数据库 `doors.db`（SQLite）：

```sql
-- 某日发言榜（日分 + 句数）
SELECT qq, score, sentences FROM daily_score
WHERE date='2026-09-01' ORDER BY score DESC;

-- 当月累计榜（含未结算的日分合计、结转、邀请分）
SELECT s.qq, u.name, SUM(s.score) + COALESCE(m.carry,0) + COALESCE(m.bonus,0) AS total
FROM daily_score s
LEFT JOIN month_score m ON m.qq=s.qq AND m.month='2026-09'
LEFT JOIN user_info u ON u.qq=s.qq
WHERE s.date LIKE '2026-09%'
GROUP BY s.qq ORDER BY total DESC;

-- 上月最终结算榜（robux 列即应发金额）
SELECT rank, qq, total, robux FROM month_score
WHERE month='2026-08' AND settled=1 ORDER BY rank;
```

## 部署

1. 解压后把**全部文件**放进 `AstrBot/data/plugins/doors_bot`（分发包是平铺的，不要再套一层目录）
2. AstrBot 插件页安装依赖并重启
3. **核对 AstrBot WebUI → 配置 → 插件配置 里的 `group_id` 与 `no_score_qqs`**：
   自 v2.5.0 起这两项的**默认值已按现网填好**（目标群号、群内不计分的机器人号），
   换群或换机器人时改配置页即可；已有配置不会被覆盖。全部可选项都在这里，
   自 v2.4.0 起插件不再读取 `.env`，包内也不附带 `.env`，旧安装残留的 `.env` 可直接删除：

| 配置项 | 默认 | 说明 |
|-|-|-|
| group_id | 现网群号（见配置页） | 目标统计群号；留空则一条都不统计，`/自检` 与启动日志都会告警 |
| no_score_qqs | 现网机器人号（见配置页） | **不会被计分的QQ**，多个用英文逗号分隔（群内机器人号、公告号）：发言不入库、不加分也不扣分，不上榜；留空则不排除任何人 |
| db_path | 自动 | SQLite **绝对路径**。留空= `<AstrBot根>\data\plugins\doors_bot_data\doors.db`（与插件同级、删插件不会带走，目录自动创建）；要放别处就填该绝对路径，别写 `../` |
| daily_score.* | 见上 | 每条分值/封顶/奖励/扣分/去重/窗口 |
| monthly_settle.* | 见上 | top_n/奖金/新人倍率/衰减/结转比例 |
| invite_bonus.* | 开 | 窗口天数/每日门槛/日均门槛/加分 |
| report.display_limit | 0 | 榜单最多显示条数，0=不限量完整显示（0 分行一律不显示） |
| scheduler.daily_job_* | 23:59 | 每日计分+扣分时点 |
| scheduler.monthly_job_* | 1日 09:00 | 月度结算时点（结算前自动补跑漏算日） |
| scheduler.member_sync_minutes | 60 | 群成员名单同步间隔 |
| scheduler.catchup_minutes | 30 | 漏算补跑间隔 |
| scheduler.timezone | 空 | 定时任务时区，如 `Asia/Shanghai`；留空跟随系统本地时区 |

改完配置需**重启 AstrBot** 才会生效（插件不会热重载定时任务）。

## 故障排查：数据没涨 / 榜单没刷新

1. 后台发 `/自检`，重点看四行：
   - `数据库:` 路径与"改动时间"。若改动时间停在昨晚，说明插件根本没在跑或写到了别的库；
     若 `遗留库探测` 列出了别的 `doors.db`，说明历史上产生过第二个库（以哪个为准需人工确认）。
   - `最近发言:` 为"无"表示 msg 表没进来消息 → 群号配错、平台不是 NapCat、或消息被过滤器挡掉。
   - `本月待补算日:` 列出日期表示 23:59 任务当时没跑（机器关机/AstrBot 未启动），
     补跑任务或 `/补跑` 会自动追回；分数会直接出现在 `/月榜`，不用等到明天。
   - `成员同步:` 为"从未"或带错误 → 未发言扣分名单与新人加成会不准。两个常见原因：
     AstrBot 刚启动时 NapCat 的反向 WS 还没连上（v2.5.1 起按 2/5/10/20/40/80/160 秒退避重试），
     以及定时任务不在消息事件上下文里、接口认不出该用哪条连接（v2.5.2 起自动带上 `self_id`）。
     等不及就发 `/同步`（先回显预览，末尾加 `确认` 才真跑），`本轮 N 次` 是这次试了几轮，
     `走 self_id` / `走 默认` 是这次靠哪条路连上的。
     若同步成功但仍报 `ApiNotAvailable`，那是 NapCat 侧 QQ 掉线/反向 WS 没连上：
     看 `logs/napcat.log` 末尾有没有登录二维码，`astrbot.log` 里有没有
     `aiocqhttp(OneBot v11) 适配器已连接。`——没有连接时消息也不会入库。
   - `邀请奖励/新人加成`一直不发：先看 `join_log` 有没有行。入群通知（`group_increase`）
     在 AstrBot 里被转成**群消息类型**，v2.5.3 起处理器放开到全部事件类型才收得到；
     且只有"有人拉人/管理员审批入群"才有邀请人，群号搜索、二维码主动入群的 `operator_id`
     为 0 或等于本人，不计邀请奖励。日志里对应 `新成员加入 <QQ> 邀请人 <QQ> 方式 <sub_type>`。
2. 主配置 `log_level` 建议临时调到 `DEBUG`，`data/logs` 之外插件失败细节会直接打在控制台。
3. 只想立刻看结果：`/补跑` → `/月榜 本月`；怀疑某天算错：`/日榜 该日` 对比 `/重置日 该日`。

## 数据库表

`msg` 原始有效候选消息 · `daily_score` 日分 · `month_score` 月总分
（total/rank/**robux**/carry/bonus/settled）· `join_log` 最新入群记录 ·
`join_history` 入群流水（≥2条=回流）· `members` 全群成员快照（in_group）·
`user_info` 昵称 · `award_history` 获奖史 · `newbie_bonus` 邀请奖发放记录 ·
`score_adjust` 手工账目调整（`/扣除` 写入的负分，按月记账，重算日分不会抹掉） · `bind` QQ↔Roblox

旧库无损迁移：启动时自动 `ALTER TABLE` 加列，已有数据保留。

## 手动运行 / 测试

在 `doors_bot` 的**父目录**执行（相对导入）：

```bash
python -m doors_bot.init_db              # 初始化/迁移数据库
python -m doors_bot.daily_score 2026-01-15  # 手算某日
python -m doors_bot.monthly_settle 2026-01  # 手动结算某月(幂等,可重跑)
python doors_bot/offline_test.py         # 离线测试套件(191项)
```

## 已知局限

- 机器人上线前进群、且上线前从未被同步到 members 快照的人，
  若其"退了又进"发生在机器人首次同步之前，无法判定为回流
- 整天没有任何消息时，无法区分"机器离线"与"群里没人说话"，
  所以补跑只重算"有发言记录却没有日分"的日期，不会替整天离线补未发言扣分
- 群内不再提供任何查询指令，所有榜单需按上节方式在后台查看

## 更新记录

### v2.5.3
- **修邀请奖励/新人加成从不触发**：入群通知 `group_increase` 带 `group_id`，AstrBot 的 aiocqhttp
  适配器把它转成**群消息**类型，而插件的入群处理器只挂了 `OTHER_MESSAGE` 过滤器 →
  通知永远进不来，`join_log.invited_by` 永远是 0（成员同步补录的记录按设计也不带邀请人）。
  现在过滤器放开到全部事件类型，由处理函数自己按 `post_type/notice_type` 认事件。
  另外"自己主动入群"时 `operator_id` 等于本人，不再记成自己邀请自己。
- **昵称清洗扩到 emoji 与反转字母**：显示前整族删掉 emoji/装饰符号（U+1F000-U+1FAFF、
  U+2600-U+27BF、几何图形、箭头、⭐ 等）与翻文字工具造出的 IPA/修饰字母（U+0250-U+02FF、
  U+1D00-U+1D7F、ǝ），宽度计算同步按 0 列；库里昵称原文不动，只影响榜单显示。
  纯 emoji 昵称清空后退回显示 QQ 号。

- **并列不再平分奖金**：口径改为"前 N 名（含并列）每人一份"。名次按并列共享名次算，
  并列第 8 名有 4 个人 → 这 4 人名次都是 8，每人各拿满 50R（原来是 4 人分一份变 12.5R）。
  因此某月获奖人数可能超过 N 人，发放名单文件头也会写明口径；月榜实时预估与结算同一条
  `compute_awards`，两边一致。
- **连续获奖衰减率默认 0.1 → 0.5**：连续 1 个月获奖下月日常分 ×0.5，连续 2 个月 ×0
  （结转分与邀请分不受系数影响）。**只改默认值**：配置页里已保存过数值的实例仍按原值走，
  需在配置页把"连续获奖衰减率"改成 0.5（或直接清空该项）才生效。
- **移除 `title_reward` 占位配置**：群头衔/等级不在 OneBot 事件里推送，NapCat 也没有对应接口，
  插件取不到原始数值，这两项配置从来没有代码读过它（用户决定：头衔奖励不进插件，纯人工判定发放）。
  删除的只是配置页里的两个空项，数据库、榜单、结算都不受影响；
  已落盘配置里残留的 `title_reward` 段会被 AstrBot 忽略，不需要手动清理。
- **群成员同步的第二层原因**：v2.5.1 的退避重试只解决了"启动太早、NapCat 还没连上"，
  但整点重跑仍然失败。真正卡住的是 aiocqhttp 的连接选择——`call_action` 必须带 `self_id`
  或者处在某条消息的事件上下文里，才能选中那条反向 WS；定时任务两者都没有，于是连接早就
  就绪了也照样抛 `ApiNotAvailable`。现在每条群消息都会记下机器人自己的号，同步时先带
  `self_id` 调，再退回枚举适配器已登记的连接号，最后才不带参数试一次；
  `/自检` 的 `走 self_id` / `走 默认` 表示这次是哪条路走通的。
- 极端情况：插件加载后一条群消息都没收到过（没有 self_id 可记）且平台不止一条连接，
  首轮同步可能仍要退回不带参数的写法，收到第一条消息后的下一轮就好了。

### v2.5.1
- **修"群成员同步从来没成功过"**：日志里每次同步都发生在 AstrBot 启动后 5~8 秒，而 NapCat
  的反向 WS 通常在那之后 0.1~4 秒才注册，此时调 OneBot 接口只会得到 `ApiNotAvailable`；
  aiocqhttp 抛的是不带实例的类，`str(e)` 为空，所以旧日志只留下一行 `rosemewbot-qq: `，
  完全看不出原因。现在：
  - 同步按 2/5/10/20/40/80/160 秒退避重试，直到拿到底为止（NapCat 明确回了错误码就不空转）；
  - 失败原因带上异常类型与 retcode，`/自检` 增加"本轮 N 次"；
  - 定时任务限单实例并合并堆积轮次，重试中的那一轮不会和下一轮同时写库；
  - 新增 `/同步 [确认]`，不用等下一个整点就能手动拉一次。
- 这份名单是未发言扣分、新人加成与邀请奖励的前提，拿到之后这三块才真正开始生效。
